# 实现约定

## 依赖和隔离

App → LunaSyncPhotoKit → LunaSyncCore。核心仅依赖 Foundation；Apple 平台采用 CryptoKit，Linux 使用经已知向量测试的流式 SHA-256 实现。没有照片上传端点、远程模型或统计 SDK。

`BackupCoordinator` actor 串行管理一个档案任务。`ArchiveStore` 为同步磁盘实现，仅在该 actor 内使用；测试可在单线程直接操作。PhotoKit 回调按顺序同步写入受锁保护的 `ResourceSink`，防止把分块数据堆积为无界异步队列。进度事件按 200ms 节流。UI 通过 AsyncStream 在主 actor 消费状态事件。

## 原始资源选择

保留 `.photo`、`.video`、`.audio`、`.alternatePhoto`、`.pairedVideo`。忽略已知的编辑结果及调整资源；遇到未知资源类型，保守地将资产列为需检查。Live Photo 必须有 `.photo` 与 `.pairedVideo`；普通照片、视频必须有对应原始资源。无法区分的重复资源描述不会自动分配身份。

资源按类型、原始文件名和 UTType 排序，为同类型分配序号。读取前重新枚举并校对资产描述；资源已删除、权限变更或描述变化时失败并等待下一轮扫描。

资产指纹由原始资源描述、拍摄时间、媒体类型、尺寸、时长及本地标识计算，不包含 `modificationDate`。这避免仅调色就重新备份；同标识且所有描述不变的内容变化不能靠元数据快速扫描检测。完整校验检测的是硬盘文件与既有导出值的差异，不重新读取照片库原片。

## 格式 v1

JSON 使用 sortedKeys 和 Foundation Codable 默认日期编码（相对 2001-01-01 的秒）。UUID 由 Codable 编码；生成路径时使用小写 UUID。资产键为 `SHA256(lowercase(sourceUUID) + "\n" + localIdentifier)`。

- 档案头：`formatVersion`、`archiveID`、`createdAt`、`sources`。
- 资产记录：`assetKey`、`sourceID`、`localIdentifier`、`generations`。
- 原始资源描述变化会建立新 generation，旧文件和记录保留。每代保存 `id`、完整资产描述及按 resource key 索引的资源收据。
- 收据包含资源描述、档案内相对路径、实际字节数、SHA-256 和完成时间。
- 每次传输使用唯一目标路径，校验错误或重新导出均不覆盖旧文件。
- 格式版本不等于 1 时禁止写入，不尝试猜测兼容性。

元数据通过同目录临时文件写入、同步、POSIX rename 和读回比对提交。记录成功后才通知 UI。路径拒绝绝对路径、空片段、`..`、反斜杠和逃出档案根的符号链接。目录遍历失败不得解释成空档案。

## 提交与恢复

1. 先持久化 generation 和未校验事务。
2. 写临时文件并计算流式 SHA-256，关闭前同步。
3. 读回临时文件，字节数和 SHA-256 必须一致且非空。
4. 持久化带预期收据的事务。
5. 将临时文件移到唯一正式路径。
6. 更新资产记录，最后删除事务。

恢复会扫描每个事务。没有校验值的临时文件删除后重传；有预期值的临时/正式文件必须读回通过，才补交记录。重复恢复是幂等的。异常正式文件保留；损坏事务不自动删除。完成记录存在但文件缺失或大小异常，会重新加入待备份列表。

新安装关联原照片库时，至少一个已记录标识必须能解析，所有重叠标识都必须有匹配的资源描述；这是保守核对，不是跨设备身份证明。用户可以建立新来源避免误跳过。

## 生命周期与缓存

前台任务期间禁用自动锁屏。进入后台申请短暂收尾时间并立即取消任务，等当前 IO 收尾后释放；不承诺后台持续传输。取消只影响未完成资源，不撤销已提交收据。

本机 SQLite 使用 WAL。`assets` 缓存每档案的资产记录，`sessions` 保存最近运行的摘要、失败清单；连接和运行结束时从硬盘重建资产缓存。缓存失败显示提示，不改变硬盘成功状态。本机运行历史不会随硬盘恢复。

首版不支持同一档案的多写入者、文件清理、恢复回相册、外部已有照片自动识别或跨设备去重。照片删除不产生硬盘删除操作。
