# Luna Sync 设计交付实施

当前视觉方向依据用户 2026-10-27 的要求：采用温暖、亲近的相册风格，但产品文案保持通用照片与视频备份定位，不限定家庭用途。早期交付稿 `Luna-Sync-Design-Handoff/LUNA_SYNC_HANDOFF.md` 和 `luna-sync-design.html` 保留为历史参考；其冷色工具风格已由本轮设计替代。继续使用原生 SwiftUI、PhotoKit 和 Quick Look。

## 页面对应

| 设计页 | 原生实现 |
| --- | --- |
| 01 欢迎 | `WelcomeView`，暖色原生纸质相册图形与通用照片备份文案 |
| 02 概览 | `OverviewView`，目录、扫描结果、主备份操作与设置入口；按后续反馈移除“最近照片” |
| 03 备份中 | `TransferView`，真实当前照片、文件名、进度与暂停 |
| 04 完成 | 同一任务页的完成态，异常项目单独列出 |
| 05 选择硬盘 | `SetupView` 第一步，系统文件夹选择器授权 |
| 06 权限和目录 | `SetupView` 第二步，完整/部分/未授权状态 |
| 07 扫描预览 | `ScanPreviewView`，元数据扫描、增量对比、确认后才导出原片 |
| 08 暂停继续 | `TransferView` 暂停态，文件级继续 |
| 09 历史 | `HistoryView`，按当前档案过滤批次，支持批次详情和硬盘资源清单 |
| 10 文件 | `DiskBrowserView`，独立授权的通用浏览器、三列网格、筛选、搜索、排序与原文件预览 |
| 11 校验 | `IntegrityView`，实际校验数、时间和问题清单 |
| 12 设置 | `SettingsView`，目录、视频、iCloud、校验说明、权限与语言 |

首页三个一级入口为“概览 / 记录 / 文件”；设置从概览右上角进入。范围选择保留日期、首尾两张区间及 ZLPhotoBrowser 逐张/滑动选择。

未配置时按照稿件 05、06 进入两个全屏步骤，再进入扫描；已配置时底部主操作进入扫描确认；首页按备份位置、照片范围、底部开始操作的顺序排列，范围使用独立卡片修改。旧照片库身份确认完成后自动继续，不要求返回概览重按按钮。

App 在前台每 3 秒检查已授权的备份目录和独立浏览目录，回到前台时立即检查。检查不写文件，也不创建新档案；备份/校验/扫描期间不重开目录。掉线会暂停使用旧目的地；恢复原目录访问后刷新连接与空间信息。临时掉线保留授权；系统无法恢复旧授权时仍需通过 Files 重新选择原目录。自动检查与手动选目录冲突时优先保留用户的新选择。

## 视觉规格

`DesignSystem.swift` 集中定义暖色主题：主文字 #40352F、主按钮 #96533F、背景 #FCF8F2、浅卡片 #F2E8DB、分隔线 #E6D9CB、辅助文字 #73655C、完成色 #50705C、提示色 #946224。浅色界面、圆润字体、轻字距、柔和卡片层次贯穿欢迎、备份、选择器、文件、历史与设置。

首页不再放置宣传口号或抒情段落。以保留爱心的纸质相册图形搭配真实备份状态和主操作，下方按顺序展示备份位置、备份范围，最后是固定在底栏上方的开始按钮；范围卡片直接打开已有照片范围选择器，位置卡片直接选择目录，选择后留在首页。未设置位置、断开连接、正在扫描或选择为空时不可开始。文字仅说明状态和功能，不限定家庭用途。未扫描时不显示虚构数字；部分失败的完成页使用警告色和真实说明。

欢迎页和目录连接示意采用 SwiftUI 绘制的纸质相册、爱心、硬盘图形；它们是装饰，不冒充用户照片，不新增位图或缩略图磁盘缓存。业务照片继续从 PhotoKit／硬盘按需加载。没有重新增加之前移除的首页“最近照片”区域。

主标题 27–32pt、说明文字 14–15pt、主按钮最小高度 56pt、按钮圆角 20pt、主要卡片圆角 22–26pt。底栏保留备份／记录／文件三个明确入口，选中项使用柔和底色。文件网格保留按需加载、密度切换和删除行为，只柔化缩略图边角。


## 与静态稿的必要差异

- 系统不向 App 提供所有物理硬盘的自动枚举权限，目录必须通过系统 Files 选择器授权，不展示伪造的“检测到的设备”。
- 未扫描时显示准备状态，不虚构新增数量。扫描后展示照片、视频、已完成与异常数量。原片总大小和预计剩余时间未取得可靠数据时不显示估算。
- 已授权不等于在线；通过实际可访问性检查更新“已连接/未连接”，空间未知时不将缺失值伪装成 0 KB。
- 文件浏览保持与备份目录独立，可以打开其他方式存入硬盘的照片。
- 写入后校验是备份完整性保证，始终开启。Live Photo 必须包含全部配套资源，不提供会破坏完整性的不实开关。
- 本机批次来自 SQLite；重装后可恢复硬盘资源清单，但不冒充已恢复本机运行批次。
- 按后续需求，照片改为直接写入选择的目录，仅 `.luna-sync` 存放记录和恢复进度；布局中的目录结构说明已同步替换。
- 首尾选择在当前相册的全部分页范围内实时展开，复用同一个 ZLPhotoBrowser 网格及大图预览，真实选中数与完成结果一致。

Debug 构建可通过 `--review-screen <页面> --capture-review` 将 App 自己的窗口截图保存在 App Documents/DesignReview 中。该功能不截取其他 App，也不启动备份。已在实际 iPhone 上检查欢迎、概览、准备、设置、历史、完成、暂停和文件页面的布局。区间算法另有万张资产与跨页选择测试。

文案维护和添加语言见 [copy-and-localization.md](copy-and-localization.md)。

自定义日期统一使用 `LunaDateField`：两个日期框宽度同为 184pt，最小触控高度 44pt；显示本地化数字日期，点击打开系统图形日历，保留起止边界和确认前草稿行为。小字在浅卡片上的计算对比度约 4.63:1，主按钮白字约 5.82:1。模拟器预览保存在 `docs/design/warm-theme/`，其中完成态为版式示意，并非真实备份收据。

日期字段和自定义范围摘要统一使用本地化的两位月份与日期格式，例如 `2026/01/02`；两个日期框保持等宽。
